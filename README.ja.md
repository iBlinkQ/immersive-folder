# Immersive Folder

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · 日本語 · [한국어](README.ko.md)

Obsidian プラグインです。あるフォルダーで作業している間、ワンクリックでファイル
エクスプローラーをそのフォルダーのノートだけに絞り込み、それ以外はあなたが戻すまで
覆い隠します。フォルダーは好きな順にドラッグして並べ替えられるので、`01_Inbox`、
`02_Projects` のような名前を付けて順序をそろえる必要もなくなります。

![Clippings フォルダーだけが読め、ほかの行はすべてスケルトンバーになったファイルエクスプローラー](docs/screenshot.png)

どのフォルダーに没入するかは、開いているファイルから自動的に決まります —— 選ぶ
必要も、別の作業に移るときに切り忘れる心配もありません。別の場所でノートを開けば、
スケルトンバーもそこへ付いてきます。何も開いていなければ没入すべきフォルダーが
存在しないので、ボタンは淡色になり「まずノートを開いてください」と伝えます。描け
ないモードを抱え込むことはしません。

読めるのはそのフォルダーと、その中身だけです。**上位**のフォルダーもバーの下に
隠れます。最上位の名前は画面上でいちばん多くを語ることが多く、そこまでの経路を
読める状態で残せば、覆い隠したかったはずの名前をそのまま差し出すことになるからです。
インデントはそのままなので、自分がどの階層にいるかは変わらず分かります。

カスタムアイコン（[Iconize](https://github.com/FlorianWoelki/obsidian-iconize)
由来）は消えるのではなくプレースホルダーのタイルになります。行の形が保たれ、覆われた
一覧もリストとして読めます。

**フォルダーを手で並べ替える**こともできます。並べ替えモードをオンにして、フォルダー
をドラッグして順序を決めます。ファイルには手を触れません —— 並べ替えメニューが置いた
場所にとどまります。ディスクに書き込まれるのは順序そのものだけで、ファイルが移動
されることは一切なく、通常のドラッグもそのまま残ります。

## なぜ必要か

- **集中。** 2000 件のノートを抱えた保管庫が、いま実際に扱っている十数件と注意を
  奪い合わなくなります。
- **会議での投影。** ひとつのプロジェクトをプロジェクターに映して説明するとき、
  部屋が読むのはそのプロジェクトだけです —— 隣のプロジェクトの名前でも、別の顧客の
  名前でも、自分用に置いてあるものの名前でもありません。生の画面に撮り直しは
  ありません。
- **画面録画。** 動画の主題になっているフォルダーだけを見せ、サイドバーの残りは
  読めないままにできます。撮る前に保管庫を整理し直す必要はありません。

## 使い方

- **ファイルエクスプローラー上部のボタン**で切り替えます。覆いが出ている間は
  アクセントカラーを帯びるので、状態がひと目で分かります。
- **`Immersive Folder: Toggle immersive folder`** はコマンドパレットからの同じ
  操作で、ホットキーを割り当てられます —— 録画のたびに切り替えるなら割り当てて
  おく価値があります。

状態は再起動をまたいで保持されます。

### フォルダーを手で並べ替える

ファイルエクスプローラー上部の**上下矢印のボタン**でフォルダー並べ替えモードに
入ります。すべてのフォルダーにハンドルが生え、わずかに漂い始めます —— これは
「いま並べ替えられます」というリストからの合図です。フォルダーを上下にドラッグして
同階層のフォルダーの中での位置を決め、もう一度ボタンを押して抜けます。

![フォルダー並べ替えモード：折りたたみ矢印がハンドルに変わり、下のファイルは終始淡いままハンドルも持たず、ドラッグ中のフォルダーには着地点を示す線が出る](docs/arrange.gif)

**参加するのはフォルダーだけです。** ファイルにはハンドルが生えず、漂わず、モード中
は淡くなります —— Obsidian の並べ替えメニューが置いた場所にとどまり続けるので、
名前順と日付順の切り替えも今までどおりに効きます。つまりツリーの骨格はプラグインが
決め、その中の一行一行は並べ替えメニューが決めます。

**フォルダーをつかむと、それを受け取れるフォルダーだけが漂い続け**、ほかの階層は
淡くなって静止します。並べ替えは常に同じ階層の中での話で、それを覚えておく代わりに
目で見られるようにしてあります。着地点は線で示されます。

変更はその都度保存され、ボタンは出入りするための入口にすぎません。

あるフォルダーで最初にドラッグした時点で、そのフォルダーのサブフォルダーの順序が
確定します。ほかのフォルダーは Obsidian に指定したとおりに並び続け、一度も並べ替え
ていない保管庫は何も保存しません。あとから作ったフォルダーはいちばん下から始まり、
ドラッグするまでそこにいます。

モード中はツリーが静止します。行を押してもノートは開かず、フォルダーも折りたたまれ
ず、ハンドルは折りたたみ矢印があった位置に座ります。見たいものは、オンにする前に
展開しておいてください。

**通常のドラッグには手を触れていません。** モードがオフなら、ノートを別のフォルダー
へドラッグする動作は以前とまったく同じです —— それは Obsidian 自身の機能で、この
プラグインは耳を傾けてすらいません。二つを時間的に切り分けることが、それぞれを
曖昧でなくします。画面の上では「そのフォルダーの下へ」と「そのフォルダーの中へ」は
同じピクセルだからです。

**没入モードと並べ替えモードは交代で使います。** 覆いは、まさに並べ替えの手がかりに
なる名前を隠してしまいます。だから一方が出ている状態でもう一方を押すと、黙って
切り替えるのではなく、どちらをどけるべきかを伝えます。待っている側のボタンは淡く
なり、ツールチップが先に閉じるべきものを示します。

### 設定

**Language（言語）** —— インターフェースは Obsidian 自体の言語設定に従います。
プラグインに同梱されているのは英語と简体中文で、ここで選べばその判定を上書き
できます。コマンド名も含め、その場で切り替わります。

**Toolbar buttons（ツールバーボタン）** —— このプラグインの 2 つのボタンのうち、
どれをファイルエクスプローラーの上部に置くか。どちらもモードのオン・オフが見える
スイッチなので、既定では両方とも見える場所にあります。片方の機能しか使わないなら
もう一方は隠せます。隠したものもコマンドパレットからは使え、何かを隠すと設定
ページからホットキー設定へ直接移動できる行が現れます。

**Keep the active file in view（アクティブなファイルを表示範囲に保つ）** ——
ノートを切り替えるたびにエクスプローラーをそのノートまでスクロールし、必要な階層を
展開して見えるようにします。これがないと、フォルダーが表示範囲外にあるノートへ
切り替えたとき、画面にはバーだけが残ります。既定でオンです。

**Collapse every other folder（ほかのフォルダーをすべて折りたたむ）** ——
切り替えのたびに、いるフォルダー以外をすべて折りたたみます。スクロールする量が
減り、ほかのフォルダーが何件抱えているかをバーが漏らすこともなくなります。開いて
いたものは没入モードを抜けるときに元に戻ります。既定でオンです。

### 見た目を変える

プラグインが描くものはすべて CSS 変数から色を取っているので、スニペット 1 つで
テーマに合わせられます。

```css
body {
  /* スケルトンバー */
  --immersive-folder-bar: var(--text-faint);
  --immersive-folder-bar-opacity: 0.5;

  /* 並べ替えモード：着地点の線、つかんでいる行、ハンドル、
     つかんでいる間にほかの階層がどれだけ淡くなるか */
  --immersive-folder-drop-line: var(--color-accent);
  --immersive-folder-drag-bg: var(--background-modifier-active-hover);
  --immersive-folder-handle: var(--text-muted);
  --immersive-folder-dim: 0.32;
}
```

着地点の線は「外観」で選んだアクセントカラーに従うので、指定しなくても今のテーマに
合います。

## できないこと

**これは視覚的な覆いであって、暗号化ではありません。** 名前はページの中に残って
います —— 開発者ツールを開ける人には読めます。カメラやプロジェクター、隣の席の人を
想定したものであって、あなたのマシンを操作できる相手を想定したものではありません。

**Collapse every other folder** をオフにすると、行がそのまま残るぶん、各フォルダーが
**何件**抱えているか、ツリーが**どれだけ深いか**はバーから伝わります。この設定を
オンのままにすればそれもまとめて折りたたまれ、残るのは、いま入っていないフォルダー
1 つにつきバー 1 本だけです。行そのものを消したいなら、[Explorer
Focus](https://github.com/davidvkimball/obsidian-explorer-focus) のような非表示系
プラグインが行ごと取り除いてくれます。

覆いが効くのはファイルエクスプローラーだけです。タブのタイトル、ノート自身の
パンくず、検索結果、クイックスイッチャーはそのままです —— エクスプローラーの検索
フィルターを開いている間も同じで、そこでは結果もほかと同様にスケルトンになります。
名前で検索したいときは覆いを外してください。

## 仕組み

行は `data-path` 属性で照合してクラスを付け、静的なスタイルシートがそれを受けて
描きます。これが効いてくる理由は 2 つあります。エクスプローラーは行を仮想化する
ので、行はいつ生成されてもおかしくなく、現れた時点ですでにスタイルが当たっている
必要があること。そして、いま入っているフォルダーが折りたたまれていて、アクティブな
行が DOM に存在しないときでも、そのフォルダー名は読めるままである必要があること
です。

ファイルが 1 つも開かれていないときは、スタイルシートはすべてを覆ったままにする
のではなく空にされます。名前のないバーの列に取り残されることは決してありません。

折りたたみとスクロールはエクスプローラー自身の行マップを経由します。これは内部
API なので、使う箇所はすべてガードしてあります。将来の Obsidian が名前を変えても、
止まるのはこの 2 つの設定だけで、覆いそのものは動き続けます。折りたたみは
アクティブなファイルが実際に変わったときだけ走り、再描画のたびには走りません。
そうでなければペインを動かすたびに操作を奪い合うことになります。

カスタム順序は Obsidian 自身の並べ替えを置き換えるものではなく、その上に重ねる
シャッフルです。エクスプローラーのプロトタイプ上で `getSortedFolderItems` に
パッチを当て、順序が記録されていないフォルダーはそのまま返します —— つまり、手で
並べ替えたサブフォルダー以外は、すべて並べ替えメニューが決めたままです。動かす
のはサブフォルダーの行だけで、しかも元から占めていたインデックスの間で動かすので、
ファイルはすべて Obsidian が置いたとおりの位置に戻ります。順序はフォルダーごとに
サブフォルダー名の並びとして保存され、実際にドラッグしたフォルダーだけが保存され
ます。

並べ替えと移動を分けているのが、この並べ替えモードです。オフのあいだ、ここは
ドラッグに一切耳を傾けません。オンのあいだは、エクスプローラー上のドラッグ
イベントを Obsidian 自身のハンドラーより先にキャプチャ段階で受け取ります ——
これは行儀の問題ではなく、安全性そのものです。放っておけば Obsidian はポインタが
とどまったフォルダーを展開し、最後に見たフォルダーへファイルを移動します。線が
描かれていない位置も含めてです。つまり、その移動は画面上の何にも予告されないまま
起こります。行にはもともと Obsidian が付けた `draggable` があるので、こちらから
ドラッグを開始する必要はありません。

パッチと、その後の再描画はどちらも内部 API で、使う前に確認し、アンロード時に
取り外します。将来の Obsidian がそれらを移したときは、並べ替え機能だけが自分で
オフになり、残りはそのまま動き続けます。

## インストール

まだコミュニティプラグイン一覧には載っていません。[最新の
リリース](https://github.com/iBlinkQ/immersive-folder/releases/latest) から
`main.js`、`manifest.json`、`styles.css` をダウンロードして
`あなたの保管庫/.obsidian/plugins/immersive-folder/` に置き、設定 →
コミュニティプラグイン から有効にしてください。

（`main.js` はビルド成果物でリポジトリには入っていません —— リリースの中か、
自分で `npm run build` を実行したあとにだけ存在します。）

## 開発

```bash
npm install
npm run dev     # ウォッチビルド
npm run build   # 型チェックして main.js をビルド
npm run lint    # コミュニティプラグイン審査が走らせるルール
npm run sync    # ビルドして sync.mjs に列挙した保管庫へコピー
```

`npm run lint` はリポジトリのルートで実行する必要があります。ルールが作業ディレクトリ
から `manifest.json` を読むためです。
