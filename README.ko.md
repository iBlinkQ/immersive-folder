# Immersive Folder

[English](README.md) · [简体中文](README.zh-CN.md) · [繁體中文](README.zh-TW.md) · [日本語](README.ja.md) · 한국어

Obsidian 플러그인입니다. 어떤 폴더에서 작업하는 동안, 클릭 한 번으로 파일 탐색기를
그 폴더의 노트만 남게 좁히고 나머지는 다시 되돌릴 때까지 가려 둡니다. 폴더는 원하는
순서대로 끌어다 놓을 수 있어서, 순서를 맞추자고 `01_Inbox`, `02_Projects` 같은
이름을 붙일 필요도 없어집니다.

![Clippings 폴더만 읽히고 나머지 줄은 모두 스켈레톤 막대가 된 파일 탐색기](docs/screenshot.png)

어느 폴더에 몰입할지는 열어 둔 파일을 보고 자동으로 정해집니다 —— 고를 것도 없고,
다른 일로 옮겨갈 때 꺼야 한다고 기억할 것도 없습니다. 다른 곳에서 노트를 열면
스켈레톤 막대도 그쪽으로 따라옵니다. 아무것도 열려 있지 않으면 몰입할 폴더 자체가
없으므로, 버튼은 흐려지면서 노트를 먼저 열라고 알립니다. 그릴 수 없는 모드를
붙들고 있지는 않습니다.

읽히는 것은 그 폴더와 그 안에 든 것뿐입니다. 그 **위쪽** 폴더들도 막대 아래로
들어갑니다. 최상위 이름은 대개 화면에서 가장 많은 것을 알려 주기 때문에, 그 경로를
읽히는 채로 남기면 가림막이 감추려던 이름을 그대로 내주는 셈이 됩니다. 들여쓰기는
그대로라서 지금 어느 층에 있는지는 여전히 보입니다.

사용자 지정 아이콘([Iconize](https://github.com/FlorianWoelki/obsidian-iconize))은
사라지는 대신 자리를 채우는 타일이 됩니다. 그래서 각 줄의 모양이 유지되고, 가려진
목록도 여전히 목록처럼 읽힙니다.

**폴더를 손으로 배열**할 수도 있습니다. 배열 모드를 켜고 폴더를 끌어 순서를
정하면 됩니다. 파일은 건드리지 않습니다 —— 정렬 메뉴가 놓아둔 자리에 그대로
있습니다. 디스크에 기록되는 것은 순서뿐이고, 파일이 옮겨지는 일은 결코 없으며,
평소의 드래그도 그대로입니다.

## 왜 필요한가

- **집중.** 노트 2000편짜리 보관소가, 지금 실제로 손대고 있는 열몇 편과 주의를
  두고 다투지 않게 됩니다.
- **회의에서 화면 공유.** 프로젝트 하나를 화면에 띄워 설명할 때, 회의실이 읽는
  것은 그 프로젝트뿐입니다 —— 옆 프로젝트 이름도, 다른 고객 이름도, 혼자 보려고
  둔 것들의 이름도 아닙니다. 실시간 화면에는 다시 찍을 기회가 없습니다.
- **화면 녹화.** 영상이 다루는 폴더만 보여 주고 사이드바의 나머지는 읽히지 않게
  둘 수 있습니다. 녹화하려고 보관소를 먼저 정리할 필요가 없습니다.

## 사용법

- **파일 탐색기 위쪽 버튼**으로 켜고 끕니다. 가림막이 올라가 있는 동안에는 강조
  색을 띠므로 상태가 한눈에 읽힙니다.
- **`Immersive Folder: Toggle immersive folder`** 명령이 명령 팔레트에서 같은 일을
  합니다. 단축키를 지정할 수 있으니, 녹화 전후로 자주 켜고 끈다면 하나 지정해 둘
  만합니다.

상태는 재시작해도 유지됩니다.

### 폴더를 손으로 배열하기

파일 탐색기 위쪽의 **위아래 화살표 버튼**이 폴더 배열 모드를 켭니다. 모든 폴더에
손잡이가 생기고 살짝 떠다니기 시작합니다 —— 이제 재배열할 수 있다는 목록의
신호입니다. 폴더를 위아래로 끌어 형제 폴더들 사이의 자리를 정하고, 버튼을 다시
눌러 빠져나옵니다.

![폴더 배열 모드를 켠 모습: 접기 화살표가 손잡이로 바뀌고, 아래쪽 파일들은 내내 흐린 채 손잡이가 없으며, 끄는 폴더마다 놓일 자리를 선으로 보여 준다](docs/arrange.gif)

**폴더만 참여합니다.** 파일에는 손잡이가 생기지 않고, 떠다니지도 않으며, 모드가
켜져 있는 동안 흐려집니다 —— 파일은 Obsidian 정렬 메뉴가 놓아둔 자리에 그대로
있고, 그래서 이름순과 날짜순을 오가는 것도 예전 그대로 동작합니다. 즉 플러그인은
트리의 뼈대를 정하고, 정렬 메뉴는 그 안의 줄들을 정합니다.

**폴더를 붙잡으면 그것을 받을 수 있는 폴더들만 계속 떠다니고**, 다른 층은 흐려지며
멈춥니다. 순서 바꾸기는 언제나 형제들 사이의 일이고, 그것을 기억하는 대신 눈으로
볼 수 있게 한 것입니다. 어디에 놓일지는 선이 보여 줍니다.

변경 사항은 그때그때 저장되며, 버튼은 드나드는 통로일 뿐입니다.

어떤 폴더에서 처음 한 번 끌고 나면, 그 폴더의 하위 폴더 순서가 고정됩니다. 다른
폴더들은 Obsidian에 지정해 둔 방식대로 계속 정렬되고, 한 번도 배열하지 않은
보관소는 아무것도 저장하지 않습니다. 나중에 만든 폴더는 맨 아래에서 시작해, 끌어
옮길 때까지 거기 있습니다.

모드가 켜져 있는 동안 트리는 가만히 있습니다. 줄을 눌러도 노트가 열리지 않고,
폴더도 접히지 않으며, 손잡이는 접기 화살표가 있던 자리에 앉습니다. 봐야 할 것은
모드를 켜기 전에 펼쳐 두세요.

**평소의 드래그는 그대로입니다.** 모드가 꺼져 있으면 노트를 다른 폴더로 끄는
동작은 예전과 똑같습니다 —— 그것은 Obsidian 자체 기능이고, 이 플러그인은 아예
듣고 있지 않습니다. 둘을 시간으로 갈라 두는 것이 각각을 분명하게 만듭니다. 화면
위에서 "저 폴더 아래로"와 "저 폴더 안으로"는 같은 픽셀이니까요.

**몰입 모드와 배열 모드는 번갈아 씁니다.** 가림막은 정렬의 근거가 될 바로 그
이름들을 덮습니다. 그래서 하나가 켜져 있는데 다른 하나를 누르면, 조용히 대신 꺼
주는 대신 무엇이 걸림돌인지 알려 줍니다. 기다리는 쪽 버튼은 흐려지고, 툴팁이
무엇을 먼저 닫아야 하는지 말해 줍니다.

### 설정

**Language(언어)** —— 인터페이스는 Obsidian 자체의 언어 설정을 따릅니다. 플러그인에
들어 있는 것은 영어와 简体中文이며, 여기서 하나를 골라 자동 판정을 덮어쓸 수
있습니다. 명령 이름까지 그 자리에서 바뀝니다.

**Toolbar buttons(도구 모음 버튼)** —— 이 플러그인의 버튼 두 개 중 무엇을 파일
탐색기 위쪽에 둘지 정합니다. 둘 다 모드가 켜졌는지 보이는 스위치라 기본적으로는
둘 다 눈에 띄는 자리에 있습니다. 한쪽 기능만 쓴다면 다른 쪽은 숨겨도 됩니다.
숨긴 것도 명령 팔레트에서는 그대로 쓸 수 있고, 무언가를 숨기면 설정 페이지에서
단축키 페이지로 바로 갈 수 있는 줄이 하나 생깁니다.

**Keep the active file in view(현재 파일을 보이는 곳에 두기)** —— 노트를 옮길
때마다 탐색기를 그 노트까지 스크롤하고, 보이게 하는 데 필요한 만큼 펼칩니다. 이것이
없으면 폴더가 화면 밖에 있는 노트로 옮겼을 때 온통 막대뿐인 화면만 보게 됩니다.
기본으로 켜져 있습니다.

**Collapse every other folder(다른 폴더 모두 접기)** —— 옮길 때마다 지금 있는
폴더를 뺀 모든 폴더를 접습니다. 스크롤할 것이 줄고, 다른 폴더가 파일을 몇 개나
품고 있는지 막대가 흘리는 일도 없어집니다. 펼쳐져 있던 것은 몰입 모드를 빠져나올
때 되돌려 놓습니다. 기본으로 켜져 있습니다.

### 겉모습 바꾸기

플러그인이 그리는 것은 모두 CSS 변수에서 색을 가져오므로, 스니펫 하나면 테마에
맞출 수 있습니다.

```css
body {
  /* 스켈레톤 막대 */
  --immersive-folder-bar: var(--text-faint);
  --immersive-folder-bar-opacity: 0.5;

  /* 배열 모드: 놓일 자리를 그리는 선, 붙잡은 줄, 손잡이,
     그리고 붙잡는 동안 다른 층이 얼마나 흐려지는지 */
  --immersive-folder-drop-line: var(--color-accent);
  --immersive-folder-drag-bg: var(--background-modifier-active-hover);
  --immersive-folder-handle: var(--text-muted);
  --immersive-folder-dim: 0.32;
}
```

놓일 자리를 그리는 선은 '모양'에서 고른 강조 색을 따르므로, 따로 일러 주지 않아도
지금 쓰는 테마에 맞습니다.

## 하지 않는 일

**이것은 시각적인 가림막이지 암호화가 아닙니다.** 이름은 여전히 페이지 안에 있고
—— 개발자 도구를 열 수 있는 사람은 읽을 수 있습니다. 카메라와 프로젝터, 옆자리
책상을 염두에 둔 것이지, 당신의 컴퓨터를 다룰 수 있는 상대를 막으려는 것이
아닙니다.

**Collapse every other folder**를 끄면 모든 줄이 제자리에 남으므로, 막대만으로도
각 폴더에 파일이 **몇 개**인지, 트리가 **얼마나 깊은지**는 드러납니다. 이 설정을
켜 두면 그것까지 함께 접혀서, 남는 것은 지금 있지 않은 폴더마다 막대 하나뿐입니다.
줄 자체가 사라지길 원한다면 [Explorer
Focus](https://github.com/davidvkimball/obsidian-explorer-focus) 같은 숨김 계열
플러그인이 아예 제거해 줍니다.

가림막은 파일 탐색기에만 적용됩니다. 탭 제목, 노트 자체의 경로 표시, 검색 결과,
빠른 전환기는 그대로입니다 —— 탐색기의 검색 필터가 열려 있을 때도 마찬가지이며,
그때는 결과도 다른 것들처럼 스켈레톤이 됩니다. 이름으로 검색하려면 가림막을 끄세요.

## 작동 방식

줄은 `data-path` 속성으로 맞춰 클래스를 붙이고, 정적 스타일시트가 그것을 받아
그립니다. 이것이 중요한 이유는 둘입니다. 탐색기가 줄을 가상화하기 때문에 줄은
언제든 만들어질 수 있고, 나타나는 순간 이미 스타일이 입혀져 있어야 합니다. 그리고
지금 있는 폴더가 접혀 있어 활성 줄이 문서에 아예 없을 때에도 그 폴더 이름은 읽혀야
합니다.

열린 파일이 하나도 없으면 스타일시트는 모두를 덮은 채로 남는 대신 비워집니다.
이름 없는 막대들의 열에 갇히는 일은 결코 없습니다.

접기와 스크롤은 탐색기 자체의 줄 맵을 거치는데, 이는 내부 API입니다. 쓰는 곳마다
방어적으로 확인하므로, 훗날 Obsidian이 이름을 바꾸면 이 두 설정만 동작을 멈추고
가림막 자체는 계속 동작합니다. 접기는 활성 파일이 실제로 바뀔 때만 실행되고 다시
그릴 때마다 실행되지는 않습니다. 그러지 않으면 창을 옮길 때마다 사용자와 다투게
됩니다.

사용자 지정 순서는 Obsidian 자체 정렬을 대체하는 것이 아니라 그 위에 덧씌운 한 번의
섞기입니다. 탐색기의 프로토타입에서 `getSortedFolderItems`에 패치를 걸고, 기록된
순서가 없는 폴더는 그대로 돌려줍니다 —— 그래서 손으로 배열한 하위 폴더 말고는
전부 정렬 메뉴가 정합니다. 옮기는 것은 하위 폴더 줄뿐이고, 그것도 원래 차지하던
인덱스들 사이에서만 옮기므로 모든 파일은 Obsidian이 둔 자리 그대로 돌아옵니다.
순서는 폴더마다 하위 폴더 이름의 목록으로 저장되고, 실제로 끌어 본 폴더만
저장됩니다.

순서 바꾸기와 파일 옮기기를 갈라놓는 것이 바로 배열 모드입니다. 꺼져 있는 동안
여기서는 드래그를 아예 듣지 않습니다. 켜져 있는 동안에는 탐색기 위의 모든 드래그
이벤트를 Obsidian 자체 핸들러보다 먼저 캡처 단계에서 받습니다 —— 이는 깔끔함의
문제가 아니라 안전 그 자체입니다. 그냥 두면 Obsidian은 포인터가 머문 폴더를 펼치고
마지막으로 본 폴더로 파일을 옮깁니다. 선이 그려지지 않은 자리까지 포함해서요.
그러면 그 이동은 화면의 그 무엇도 예고하지 않은 채 벌어집니다. 줄에는 이미
Obsidian이 붙인 `draggable`이 있으므로 여기서 드래그를 시작할 일은 없습니다.

패치와 그에 뒤따르는 다시 그리기는 모두 내부 API로, 쓰기 전에 확인하고 언로드할 때
되돌립니다. 훗날 Obsidian이 그것들을 옮기면 순서 기능만 스스로 꺼지고 나머지는
그대로 동작합니다.

## 설치

아직 커뮤니티 플러그인 목록에는 없습니다. [최신
릴리스](https://github.com/iBlinkQ/immersive-folder/releases/latest)에서
`main.js`, `manifest.json`, `styles.css`를 내려받아
`당신의보관소/.obsidian/plugins/immersive-folder/`에 넣고, 설정 → 커뮤니티
플러그인에서 활성화하세요.

(`main.js`는 빌드 산출물이라 저장소에는 없습니다 —— 릴리스 안에, 또는 직접
`npm run build`를 실행한 뒤에만 존재합니다.)

## 개발

```bash
npm install
npm run dev     # 감시 빌드
npm run build   # 타입 검사 후 main.js 빌드
npm run lint    # 커뮤니티 플러그인 심사가 돌리는 규칙
npm run sync    # 빌드한 뒤 sync.mjs에 적힌 보관소로 복사
```

`npm run lint`는 저장소 루트에서 실행해야 합니다. 규칙이 작업 디렉터리에서
`manifest.json`을 읽기 때문입니다.
